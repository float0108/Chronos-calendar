# 🔍 Tauri 项目重构分析报告

## 📈 总体评估
- **代码总行数**: 前端 ~11,487 行 / 后端 ~4,216 行
- **潜在问题数**: High: 5 / Medium: 8 / Low: 6
- **预估重构工时**: 3-4 人天

---

## 🚨 高优先级问题 (必须修复)

| 维度 | 文件 | 行号 | 问题描述 | 修复建议 | 风险等级 |
|------|------|------|----------|----------|----------|
| **🔐 安全** | `capabilities/default.json` | 35-37 | `fs:default` + `fs:allow-read-text-file` + `fs:allow-write-text-file` **无路径限制**。恶意的 HTML/JS 文件可被写入并通过 `core:window:allow-eval` 执行 XSS | 添加 `fs:scope` 限制只读 `/app_data/` 目录；移除 `allow-write-text-file` 改用对话框让用户选择保存位置 |
| **🔐 安全** | `src-tauri/src/windows.rs` | 全部 | `SetWindowLongPtrW` 子类化无边界检查，Windows API 直接硬编码 | 验证 hwnd 属于本应用窗口；考虑用 Tauri 原生 `always_on_bottom` 替代 |
| **🔐 安全** | 后端所有命令 | - | 后端直接 `unwrap()` 可能导致 panic 并让前端崩溃 | 统一错误类型 `AppError`，所有命令返回 `Result<T, AppError>` |
| **⚡ 性能** | `useSchedules.ts` | 411-421 | `loadAllSchedules` 只加载当年数据(01-01 到 12-31)，跨年日程会被截断 | 使用动态范围如 `startDate = today - 2 years`, `endDate = today + 1 year` |
| **⚡ 性能** | `src/composables/useSettings.ts` | 78 | `extractCommonParts` 每次保存都执行 JSON.parse | 缓存或简化合并逻辑 |

## ⚠️ 中优先级问题 (建议修复)

| 维度 | 文件 | 行号 | 问题描述 | 修复建议 | 风险等级 |
|------|------|------|----------|----------|----------|
| **🗑️ 死代码** | `NoteWindow.vue` | 207-217 | **重复的 watch**：`watch([title, content], ...)` 定义了两次，内容完全相同 | 删除重复的 watch 块 |
| **🗑️ 死代码** | `src/composables/useSystemTheme.ts` | 全部 | 与 `useSettings.ts` 中 `initSystemThemeDetection` **功能完全重复**，两套系统主题检测并存 | 合并到 `useSettings`，删除此文件 |
| **🗑️ 死代码** | `src/composables/useTaskTheme.ts` | 全部 | 与 `useTheme.ts` 功能重叠，且 `TodoWindow.vue` 直接用 `useThemeStyle` (useTaskTheme) 而非 `useTheme` | 统一为 `useTheme`，消除并行 |
| **🔁 DRY** | 后端 `commands/database.rs` | 85-91 等 | **每个命令都有重复的 DataChange 通知模式**：构建 struct → 调用 `notify_change` | 抽离为 `DbState::notify(&self, entity, action, id, data)` 公共方法 |
| **🔁 DRY** | 后端 `commands/database.rs` | 160-179 | `db_update_schedule_content` 和 `db_update_schedule_description` 只有 field 名不同，逻辑完全相同 | 合并为 `db_update_schedule_field(id, field: String, value: serde_json::Value)` |
| **🔁 DRY** | 前端 `database.ts` | 363-399 | `importAndMergeData` 中手动做 camelCase→snake_case 转换，BackupData 各处重复 | 创建 `toBackendFormat()` 工具函数复用 |
| **🧩 提取** | 前端 | - | 39 个 `invoke()` 调用分散在 `database.ts`，无统一错误处理/loading 状态 | 创建 `useCommand(command, options?)` composable 封装 `{ data, loading, error, execute }` |
| **🧩 提取** | 前端 | - | 3 套 undo 系统（`useUndoHistory`, `useEditHistory`, `useScheduleUndo`）概念重叠 | 合并为基础 `useUndo<T>(options)` + 特定域扩展 |

1. **立即修复**：安全漏洞 (capabilities 权限过大、子类化 XSS 风险)
2. **本周修复**：重复 watch bug、死代码清理
3. **下期重构**：统一 undo 系统、通知系统、主题系统
4. **长期优化**：Tauri command 封装 composable、后端命令模式简化
